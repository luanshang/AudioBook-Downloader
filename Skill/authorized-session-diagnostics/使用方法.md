# 使用方法

## 1. 安装工具

从 [Reqable 官方网站](https://reqable.com/zh-CN/) 下载与你的系统匹配的版本，并只从官方渠道安装。首次使用时阅读其隐私、证书和数据存储说明。

## 2. 准备授权测试

1. 确认测试设备、账号和应用均属于你，或已取得明确授权。
2. 关闭与问题无关的应用，减少误采集。
3. 在 Reqable 中启动本地捕获，按官方文档完成系统代理或设备代理配置。
4. 仅对目标应用执行一次可复现操作，例如登录状态检查或播放地址请求。

不要为了取得凭证而开启全量长期捕获，也不要尝试绕过验证码、风控、权限检查或付费限制。

## 3. 观察请求

使用域名、路径和 HTTP 方法过滤目标请求。记录以下非敏感信息：

- 请求时间和客户端版本
- HTTP 方法、域名、路径和状态码
- 服务端返回的公开错误码和错误消息
- 问题是否可以稳定复现

查看 Header、Cookie、Authorization 和 Body 时只用于本地确认字段是否存在，不要复制其值。需要截图或导出报告时，先把值替换为 `<REDACTED>`，并删除完整请求体中的签名、Token、设备标识和临时 URL。

## 4. 认证失败诊断

- “请登录”“会话无效”：先在官方客户端重新登录，并使用应用提供的正规认证流程。
- “请验证”“需要验证”：按照官方客户端提示完成验证；这不等同于 Token 已过期。
- 明确的 “token expired”“Token 过期” 或类似错误：按照官方流程重新认证并撤销旧凭证。
- 只有在服务端错误信息明确支持时，才能判断 Token 已过期；不要仅凭 HTTP 401、403 或其他通用状态码猜测具体原因。

本 Skill 不生成、解密、重放或批量导出认证凭证，也不将 Web Cookie 当作 App 认证参数使用。

## 5. 结束与清理

1. 停止 Reqable 捕获并关闭代理。
2. 删除本地导出文件、截图和临时日志中的敏感内容。
3. 对曾经暴露的 Cookie、Token、密码或 App 认证参数执行退出登录、撤销或重新生成。
4. 分享报告时只保留脱敏后的路径、状态码和错误消息。
